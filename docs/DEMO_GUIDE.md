# RoadWatch 演示流程指南

本指南按 **5 分钟**节奏安排,覆盖岗位 JD 的核心能力:时序异常检测、视觉检测、事件处置闭环、真实地图、视频流检测、多源接入。

## 准备

- 启动服务:`.\.venv\Scripts\python.exe scripts/dev.py`(首次会自动播种演示数据)
- 打开浏览器访问 http://127.0.0.1:8010
- 如需真实 YOLO 检测框,设 `DETECTOR_MODE=yolo`;演示固定框用默认 `demo`

---

## 第一幕:运行总览与真实地图(1 分钟)

**目标**:展示系统整体态势 + 真实地图可视化。

操作:
1. 打开首页,顶部四张统计卡片:监测点、待处置事件、高优先级、检测任务。
2. 中部"监测点分布"是 **Leaflet + OpenStreetMap 真实地图**,监测点按经纬度落点;绿色=正常,红色=有待处置事件。
3. 点击地图标记可弹出监测点信息,并联动下方车速趋势图。

**讲解要点**:地图替代了原来的离线坐标图,符合 JD"事件面板/地图"要求;标记颜色反映事件状态。

---

## 第二幕:新建监测点 + 时序异常检测(1.5 分钟)

**目标**:展示车速基线 + 拥堵指数 + 稳健偏差(MAD)的时序异常算法,以及 WebSocket 实时推送。

操作:
1. 左侧导航 → "监测点管理"。
2. 填写:名称=`演示路段A`,纬度=`31.2304`,经度=`121.4737`,基线车速=`60`,提交。
3. 回到"运行总览",滚动到"接入交通指标":
   - 监测点选"演示路段A"
   - 车速=`12`,拥堵指数=`0.9`,车辆数=`50`
   - 提交
4. **观察**:页面顶部弹出"新事件:拥堵(高)"通知(WebSocket 实时推送);事件队列条数 +1;新事件来源="时序分析",优先级=高。

**讲解要点**:
- 算法:新监测点无历史数据,用基线车速 60;偏差分 `(60−12)/5 = 9.6`,同时拥堵≥0.8 且车速<30,判定为 `congestion`。
- 自动定级 high,120 秒内同类型事件去重。
- WebSocket 推送说明系统支持实时告警,不是轮询。

---

## 第三幕:事件处置流转(1 分钟)

**目标**:展示事件生命周期状态机 + 审计记录。

操作:
1. 在事件队列点新拥堵事件的"查看处置"。
2. 弹窗填备注=`已通知路政现场处置`,点"处理中"(acknowledged)。
3. 处置记录区出现该条操作;再点"已解决"(resolved)完成闭环。

**讲解要点**:状态机 `open→acknowledged→resolved/dismissed`,乐观锁防并发,全程审计可追溯。

---

## 第四幕:图片视觉检测(1 分钟)

**目标**:展示异步任务队列 + 视觉检测。

操作:
1. 左侧导航 → "图片检测"。
2. 选监测点,上传一张道路图片(如 `datasets/incoming/` 下的示例图)。
3. 点"创建检测任务",任务进入 `queued`,Worker 异步调用推理服务。
4. 几秒后状态变 `succeeded`,图片上叠加检测框和类别置信度。

**讲解要点**:
- 任务队列用租约(lease)抢占,支持多 Worker 并发和崩溃恢复。
- 可选 Redis Stream 加速通知(`REDIS_URL`),无 Redis 自动回退数据库轮询。
- demo 模式返回固定框;yolo 模式加载真实权重(可通过模型版本管理接口切换)。

---

## 第五幕:视频流实时检测(可选,1 分钟)

**目标**:展示 JD 要求的"图像/视频分析"。

操作:
1. 左侧导航 → "视频实时检测"。
2. 视频源选"视频文件"(或"摄像头"调用本机摄像头)。
3. 抽帧间隔默认 1 秒,置信度阈值 0.4,点"开始检测"。
4. 画面实时叠加检测框,右上角显示推理延迟。

**讲解要点**:抽帧 → 调用 `/predict` → 叠加框,适用于边缘设备对摄像头/RTSP 流做实时分析。

---

## 第六幕:数据集标注与 AI 训练闭环(可选,2 分钟)

**目标**:展示从标注到训练到部署的完整 AI 开发能力(回应"有没有 AI 训练能力"的追问)。

操作:
1. 左侧导航 → "数据集与标注" → 新建数据集。
2. 上传道路图片,在图片上拖拽画框,选择 6 类目标之一(积水/障碍/事故/坑洞/油渍/垃圾)。
3. 勾选"预标注"上传,系统用当前模型自动生成初始框,人工微调。
4. 在数据集图片列表批量设置 train/val/test 分桶。
5. 导出 YOLO 格式 ZIP,解压后训练:
   ```powershell
   .\.venv\Scripts\python.exe scripts\ml.py train --weights models\base.pt --data <解压目录>\data.yaml --epochs 100
   ```
6. 训练完成后注册模型版本:`POST /api/v1/model-versions`,设置激活,推理服务自动加载。

**讲解要点**:完整的"数据→标注→训练→部署→推理"闭环,证明具备 AI 开发能力而非只会调 API。

## 性能与架构亮点(面试可主动提及)

| 能力 | 证据 |
|---|---|
| 微服务架构 | API / Worker / Detector 三进程分离,可独立伸缩 |
| 高并发任务队列 | 数据库租约抢占 + Redis Stream 通知,崩溃自动恢复 |
| 多源数据接入 | HTTP API + MQTT(`backend.mqtt_ingest`) |
| 推理性能监控 | `/stats` 返回 p50/p95/p99/吞吐;INT8 量化、批处理 |
| 边缘部署 | ONNX 导出 + INT8 量化 + Jetson/TensorRT 文档 |
| 模型版本管理 | 注册/激活/切换,推理服务热加载激活版本 |
| 实时告警 | WebSocket 推送,新事件秒级触达看板 |

## 常见问题应答

- **"模型准不准?"** → 工程链路完整,识别精度取决于标注数据量;当前演示数据有限,可在数据集模块持续标注扩充。
- **"支持多少并发?"** → Worker 可水平扩展;Redis Stream 模式下任务分发延迟 < 100ms;提供压测脚本 `scripts/load_test.py`。
- **"边缘怎么部署?"** → 见 `docs/EDGE_DEPLOYMENT.md`,ONNX Runtime + INT8 量化,Jetson 上用 TensorRT FP16。
